# demo

The kit demo app (`dev.krifmaz.kit.demo`): every kit feature on one scrolling screen and the pages it opens, against
a server kept in memory, so it needs no network and no account.

| What | Where |
| --- | --- |
| Theme picker (Encore, Dark, OLED, Light, System) and the accents | top of the screen |
| Buttons, badges, the "⋯" menu, tabs, card, field, empty state | Buttons and badges, Card and field |
| Toasts: info, ok, error with Copy, Undo, duplicates merging | Toasts |
| Details dialog, confirm dialog, type-to-confirm | Details and confirm dialogs |
| What's new popup and the changelog | What's new |
| Self-updating (looks at the kit's own releases; the demo never installs) | Updates |
| Notice banner with Check again ("Break the mail server" brings it back) | top of the screen, Notice banners |
| Bug reports (list, report, new report with pictures), Send the crash log, Crash the app | Bug reports and crash log |
| Offline banner and sheet, the reason, changes that wait and go out when back | Offline mode ("Server down") |
| Server settings from a schema (every field kind, `when` rules, a secret to Show/Copy, advanced, a framed block, Test and Save) | Settings → Server settings |
| Diagnostics with Copy report, and App crashes | Settings → Diagnostics |
| Drag and drop and the file picker | Drag and drop |

How it is built:

- `DemoApp` sets the kit up as an app does: `CrashLog.install`, `KitApp.init`, `UpdateRules.source`.
- `DemoBackend` is the server: it answers every `KitRoutes` route the way the contracts say, from memory.
  `DemoServer` puts it behind an OkHttp interceptor for the host `demo.invalid`, so every kit call (JSON, multipart
  uploads, pictures, the health check) reaches it through the real client code.
- `assets/settings-schema.json` is the server's settings schema (kit-compose's tests check it too).
- `DemoServerTest` drives the kit's own calls (bug reports, settings, notices, What's new, diagnostics, offline
  check) against the demo server.

```sh
gradle -p android :demo:testDebugUnitTest :demo:assembleDebug   # test and build
gradle -p android :demo:installDebug                             # on a connected device
```

It turns on the debug checks (`KitPerf`) and ships a Baseline Profile generated by `:baselineprofile`. The release
build is signed with the debug key: the demo is never published; the benchmarks install it.
