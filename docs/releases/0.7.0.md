## Kit 0.7.0

Apps on the kit can now update their own server from the app, when it runs in Docker.

- **Update now.** With the Docker socket mounted, the server pulls the new image and starts a short-lived helper from it. The helper stops the server's container, makes a new one from the new image with the same settings (ports, volumes, networks, environment, restart policy), and starts it.
- **Safe roll-back.** If the new container can't be made, can't start, or stops again within 20 seconds, it is removed and the old one comes back. If the new server had already begun migrating its database, the helper starts it again instead, and keeps the old one stopped for a way back by hand.
- **Checks first.** Before anything is stopped, the helper checks that the image holds the version its tag names and can read the server's database.
- **Plain words.** The app says in plain words why Update now isn't available here (no socket, not writable, not in a container, started with `--rm`, a Swarm task).
- **A record of every step.** The last update's steps are kept with the step that failed and Docker's own error, ready to copy.

New crate: `kit-server-selfupdate`. The app gives its name, image and program, and its own checks.
