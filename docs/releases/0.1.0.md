# Kit v0.1.0 — the first release

The neutral shared base for every Krifmaz app, built once and configured per app (name, version, logo,
routes, words, settings schema, changelog source, release targets). Apps pin this tag.

## What's in it
- **Design tokens** (`design/`): one `tokens.json` generating CSS variables, a Compose theme, an Iced theme and
  Flutter ThemeData. Themes: Encore (the default, charcoal and cream), Dark, OLED black, Light, plus accents
  and presets.
- **Contracts** (`contracts/`): prose and OpenAPI for health, changelog, notices, bug reports, diagnostics,
  settings schema and the update feed.
- **Seven server crates** (`kit-server-*`, Axum) on `kit-server-core`: health, What's new, notices, bug reports
  and crash logs, diagnostics, settings from one `settings.toml`, and updates. Their storage sits behind a
  trait per crate, with a SQLite store and a Postgres store (sqlx, `postgres` feature) in the kit's own
  `kit_*` tables made by migrations.
- **kit-rules**: the client decisions as plain Rust (toasts, details, What's new, versions, update detection,
  notices, offline and outbox, uploads, dialogs, bug reports, diagnostics), with the kit's default words.
- **kit-leptos** (web): What's new, the self-updating web app, notice banners, smart toasts, copyable errors,
  the bug report sheet, diagnostics, settings from a schema, offline banners, confirm dialogs and drag and
  drop, with the kit's own stylesheet.
- **kit-iced** (desktop) and **kit-compose** (Android, published to GitHub Packages): the same features.
- **Shared workflows**: `kit-ci`, `kit-release` (a normal vX.Y.Z on every push to main), `kit-docker` (GHCR
  `:<version>` and `:latest`), `kit-android` (signed APK) and `kit-desktop` (Windows, Linux, macOS).
- **Template**: `cargo generate krifmaz/kit template` gives a server on SQLite, a Leptos web app, an optional
  Android app, a desktop app, a distroless non-root Dockerfile, CI on the shared workflows and a CLAUDE.md.
  Its demo runs every kit feature on web, Android and desktop, and the kit's CI proves it on every pull
  request (plus a test run of the server crates on Postgres).

## From here on
Every merge to main ships its own release: PATCH by default, MINOR or MAJOR when the pull request adds
`docs/releases/<version>.md`.
