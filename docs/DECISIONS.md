# Decisions

One line per non-obvious call (DESIGN.md first, then Encore's behaviour, then common sense).

- 2026-11-04 · The design docs went straight to main as the first commit, since an empty repo has no base for a PR; everything after goes through PRs.
- 2026-11-04 · Tokens keep Android's current differences from the web (logo accent in every palette, cream OLED text, charcoal accent on Light) as `compose.overrides`, so the generated Compose theme equals Encore's exactly.
- 2026-11-04 · The generated CSS is only the theme-variable blocks of Encore's app.css (lines 1–72); the rest of the stylesheet stays Encore's and is reused unchanged by kit-leptos.
- 2026-11-04 · The notice contract keeps Encore's object ({ok, text, checking}) and adds `id` and `severity`; Encore keeps its paths, other apps get `/api/notices`.
- 2026-11-04 · Diagnostics keeps Encore's check shape ({name, kind, ok, detail, request}) and adds optional `status` and `fix`.
- 2026-11-04 · The kit's release workflow makes no release until docs/releases/0.1.0.md exists, so the first tag is v0.1.0 once §18 passes.
- 2026-11-04 · rustfmt max_width 140 (Encore's code is written to long lines; fmt is now enforced in CI).
- 2026-11-04 · Package names: Rust crates `kit-*`; Android `dev.krifmaz.kit:kit-compose` (as DESIGN.md §15).
- 2026-11-04 · kit-release.yml is called twice per run (`stage: prepare` → version, web app, server; `stage: publish` → notes, SHA256SUMS, release) instead of nesting kit-docker/-android/-desktop inside it: a `./` call inside a workflow used from another repo is not reliably resolved to the kit, and the version must be known before the image and apps build.
- 2026-11-04 · App-specific parts of Encore's release (install notes, browser extension, the compose file, old installer names) stay in Encore and reach kit-release as small inputs (`files`, `notes`, `carry-over`, `carry-over-drop`, `keep-drop`), so the kit holds no Encore wording.
- 2026-11-04 · Signing secrets are passed to kit-android/kit-desktop by name; `secrets: inherit` only works within one organisation and Encore and the kit belong to a user account.
- 2026-11-04 · kit-android's Baseline Profile check is an input (`baseline-profile`), off for Encore until its app has one (track C), so the switch changes nothing.
- 2026-11-04 · Every merge to Encore's default branch is now a normal vX.Y.Z release (DESIGN.md §19) instead of a hotfix-<v>.<run> build; the push trigger keeps Encore's docs-only and `[skip hotfix]` exceptions, skips the speed table like the hotfixes did, and the server's hotfix channel keeps working (it also counts full releases).
- 2026-11-04 · kit-rules toasts: web, desktop and Android differ (3/3/10 errors, others uncapped/5 in all/3, 4.2 s fade 0.4 s/4.2 s/4 s, a repeated error dropped vs moved to newest, blank skipped only on Android), so `ToastPolicy::{web,desktop,android}` keep each exactly.
- 2026-11-04 · kit-rules toasts expire at `at + life` (timer semantics, as the web and Android); the desktop's `elapsed > life` differs by one tick at most.
- 2026-11-04 · kit-rules changelog holds the notes parser (`parse`, `plain`, `short`, `unseen`) too, not only the grouping, so kit-server-changelog and every client read notes the same way; the app name is a parameter ("Encore" in Encore).
- 2026-11-04 · kit-rules has a `version` module (Encore's `encore_core::version` and `base`), with the `\d+(\.\d+)+` regex written out by hand so the crate needs no regex engine.
- 2026-11-04 · Words that name the app ("A new version of Encore is ready", "This server runs Encore …", the 502 reason) and keys/prefixes (`encore-web-`, `encore.update.tried`, `encore:version`, `encore-shell-`, `encore.offline.me`) take the app's name; Encore passes "Encore" and gets its exact strings.
- 2026-11-04 · The outbox's owner is a trait (`Outbox<i64>` = web `user_id`, `Outbox<String>` = Android `owner` `<server>|<username>`) so both documents keep their fields; Android's parse drops entries without a song, the web's does not.
- 2026-11-04 · `Outbox::parse` reads entry by entry, so one unreadable play no longer empties the whole document as the web's serde parse did (only affects corrupt files).
- 2026-11-04 · `plays_body` returns a serializable struct, not a `serde_json::Value`, so the field order (`track_id, seconds, played_at`) matches Android's body byte for byte without serde_json's `preserve_order`.
- 2026-11-04 · details: the web's blank-title rule (`trim().is_empty()`) is `details::title`, Android's empty-only rule is `details::title_android`; Encore has no "is it cut off" rule in code (CSS/Compose decide), so kit-rules has none.
- 2026-11-04 · Offline reasons are classified from a platform-neutral `Failure` enum (Dns, Timeout, Refused, Tls, Other) that each client maps its errors to, with Android's words.
- 2026-11-04 · Android-only window placement (`ToastRules.covered`, `lift`, `drop`) stays in kit-compose: it is Android window and inset logic, not shared rules.
- 2026-11-04 · kit-compose compiles the theme straight from design/out/KitTokens.kt (an extra source dir), so the library can't drift from the tokens and nothing is copied.
- 2026-11-04 · kit-compose pins the same AGP, Kotlin, Compose BOM and library versions as Encore's Android app, so an app that includes the kit's build gets one of each.
- 2026-11-04 · App identity (name, version, User-Agent) reaches the kit through `KitApp.init(...)` at start-up, so messages like "Encore needs access…" stay word for word.
- 2026-11-04 · Kit names drop the app name where Encore had it in code only (EncoreButton → KitButton, EncoreField → KitField, EncoreJson → KitJson); nothing users see changes.
- 2026-11-04 · Encore's Android tests for code that moved (ToastRules, offline, bug, update, schema rules) moved with it into kit-compose/src/test, assertions unchanged.
- 2026-11-04 · Encore Android builds kit-compose from source (settings.gradle.kts fetches the kit at the commit/tag in clients/android/kit.properties and includes it): GitHub Packages needs a token to read even public packages, which Encore's CI doesn't have.
- 2026-11-04 · Encore Android doesn't show the kit's What's new popup (it never had one; adding it would be a visible change DESIGN.md doesn't ask for on Android); the component is in the kit, tested, for other apps.
- 2026-11-04 · android-publish.yml also runs after each release workflow run, since releases made with GITHUB_TOKEN start no `release` event.
- 2026-11-04 · kit-iced components hold no network code: they keep state, draw it and return what the app must request (Encore keeps reqwest, rfd and its API paths), so any app can use them.
- 2026-11-04 · kit-iced has one active look (`theme::set`/`look`, as Encore's desktop); Encore's `theme.rs` re-exports it, so Encore and the kit share one look.
- 2026-11-04 · App names in kit-iced words are parameters (`update::describe(p, "Encore")`, `whats_new::changelog(state, "Encore")`), giving Encore's exact words.
- 2026-11-04 · Encore desktop tests of code that moved into kit-iced move with it (ported, same assertions); tests of Encore's own code stay in Encore.
- 2026-11-04 · kit-iced `bug_report` keeps Encore desktop's checks (title and description required, 6 files, 8 MB each); the 200/20 000/120-character limits of contracts/bug-reports.md stay the server's, as in Encore.
- 2026-11-04 · kit-iced turns on iced's `image` feature: the bug report picker's thumbnails need `image::Handle::from_path`, as in Encore.
- 2026-11-04 · kit-iced form: table texts are `Cow<'static, str>` and option lists a static-or-owned enum, so Encore's const table and the server schema share one `Field`/`Card`; Encore's `Card { .. }` literal becomes `card! { .. }`.
- 2026-11-04 · kit-iced form: Encore's hard-coded "no Show saved for vpn_wireguard_config" becomes `Form::never_shown(keys)`, set by the app; a `key!=value` rule is `When { not: true }`; clearing a secret is its own `Msg::Cleared` (same toasts).
- 2026-11-04 · kit-iced diagnostics: a `status` of ok/warn/fail is the kit's level, any other `status` stays Encore's HTTP badge; warn draws in the warn colour; `fix` is a muted line under the detail (Encore never sends it).
- 2026-11-04 · kit-leptos: Leptos pinned `=0.8.23` (latest stable; 0.9.0-rc1 is a pre-release), so kit-leptos needs Rust 1.88; the lock keeps Encore's wasm-bindgen 0.2.129, web-sys/js-sys 0.3.106 and wasm-bindgen-futures 0.4.79 so Encore adopts it without a `cargo update`.
- 2026-11-04 · kit-leptos: kit-leptos markup tests render with the `ssr` feature (dev-dependency only) and compare a canonical DOM (attribute sets, class words, text, whitespace and markers ignored), because server rendering always writes `class` last; exact bytes and attribute order are checked in the browser by the demo.
- 2026-11-04 · kit-leptos: kit-leptos keeps Encore's attribute order with a leading `{..()}` spread and avoids empty `<!---->` placeholders with `{..html(s)}` plus a `{""}` child; placeholder comments left inside kit-only subtrees (settings cards, Diagnostics) are accepted, as they change no element or text.
- 2026-11-04 · kit-leptos: `#toasts` holds one separately mounted view per toast (no `<For>`), so toasts other Encore code appends by hand stay in arrival order and the container holds no list marker.
- 2026-11-04 · kit-leptos: Each modal is its own mount appended to `#modal-root`, synchronously, so `modal::open` returns the real elements at once and Encore's `ui::modal` callers can keep using `m.qs(..)` right after.
- 2026-11-04 · kit-leptos: The connection banner is dropped synchronously when it goes (as Encore's `remove()`), not through a signal, so code that checks for `#conn-banner` right after sees it gone.
- 2026-11-04 · kit-leptos: Server calls go through a replaceable `api::Backend` (default `HttpBackend`, a port of Encore's `api.rs`), so the demo and tests run without a server.
- 2026-11-04 · kit-leptos: The schema settings model (`schema_form::schema`) and the settings form's words stay in kit-leptos for now; they move to kit-rules when a second client draws the form.
- 2026-11-04 · New kit-rules modules `bugs`, `diagnostics` and `dialogs` hold the words and decisions of the bug report sheet, the Diagnostics page and the shared dialog buttons, copied verbatim from Encore.
- 2026-11-04 · kit-leptos: Diagnostics: a numeric `status` draws Encore's HTTP badge; a kit server's string status (`warn`/`fail`) sets the level, and its `fix` line is shown under the check; Encore's VPN sub-block and app-specific blocks (Soulseek, backups, crashes) are left to `DiagHooks` and children.
- 2026-11-04 · kit-leptos: Error-toast Copy and Close use per-button handlers with `stop_propagation` instead of relying on Encore's page-wide click listener (`details.rs` `init`), so a toast works without it; the listener still serves hand-written `[data-copy-text]` buttons, and the user sees the same.
- 2026-11-04 · kit-leptos: The update toast lives in the toast store, placed after the toasts that were there when it came, so it sits where Encore's `appendChild` put it.
- 2026-11-04 · kit-leptos: The demo links `design/out/tokens.css` plus a copy of Encore's `app.css` after its colour tokens (with a SOURCE note), because the kit ships no component stylesheet yet; the copy is demo-only.
- 2026-11-04 · kit-leptos: Components match Encore's `outerHTML` exactly (white space text nodes, attribute order, no placeholder comments), not only the canonical DOM, because Encore's switch must show no change and its shots compare is byte-exact.
- 2026-11-04 · kit-leptos: An app's own HTML builders go into a component through `html::raw` (parsed with a `<template>`, mounted without wrapper) instead of being ported to `view!`, so Encore-only blocks stay in Encore as hooks.
- 2026-11-04 · kit-leptos: Open modals are kept in a registry until closed, and `modal::close_all` drops them, so a dialog's handlers live as long as the dialog and a router that empties `#modal-root` leaves nothing behind.
- 2026-11-04 · kit-leptos: The settings card's reactive result line is drawn only when the app gives `out`, since Encore's card has none.
- 2026-11-04 · Encore web switch: `render_shell` still adds its document `contextmenu`/`click` listeners and the storage-meter interval on every draw, as before; the shell itself is mounted once, so its own button handlers no longer repeat. Adding the document listeners once would change what a right-click does after an account refresh (the ⋯ button is pressed once instead of once per draw), a visible change, so it is left for its own PR.
- 2026-11-04 · Encore web switch: a later `render_shell` redraws only the account's parts of the Leptos shell and empties the two badges until their next answer, which is what the hand-written full redraw showed.
- 2026-11-04 · Encore web switch: Encore registers its own `api.rs` as the kit's `api::Backend`, so the kit's calls carry the same headers, errors and `encore:server-*` events as the pages' calls.
- 2026-11-04 · Encore web switch: Encore's parity test also scans the kit-leptos and kit-rules sources (found with `cargo metadata`), since the words the kit draws for Encore now live there.
- 2026-11-04 · Encore web switch: the wasm grows 2.51 MB → 2.90 MB (+15.7 %, mostly Leptos' own generic code); accepted, since DESIGN.md §10 asks for Leptos and its guard rail is speed, which is unchanged (first load and every navigation median within run-to-run noise, no long tasks). Shrinking it by turning static views into raw HTML strings is left for the page-by-page step.
- 2026-11-04 · The server crates share an eighth small crate, `kit-server-core` (error answer, `Host`/`Db` traits, `SignedIn`/`Admin`, version compare, `SqliteDb`, `TestHost`), so the seven feature crates don't each repeat them.
- 2026-11-04 · Errors answer `{"detail": …}` as Encore's `encore_core::error` really does; the contracts said `{"error": …}`, which no Encore client reads, so the contracts were corrected.
- 2026-11-04 · The kit crates take the app's database as JSON rows and parameters over SQL strings (Encore's `encore_db` shape), so they keep Encore's SQL unchanged; apps without a database layer use `SqliteDb`.
- 2026-11-04 · Admin is the account's `role` being `admin` or `owner` (Encore's `perms::is_admin`); an app can override `Host::admin` to keep its own checks and words.
- 2026-11-04 · kit-server-changelog's notes parser and build-script embedding work without its server half (`default-features = false`), so an app's build.rs needs no Axum.
- 2026-11-04 · kit-server-settings has two features, both on by default: `toml` (read, check and generate settings.toml) and `server` (Store and routes); an app's build script takes only `toml`, so axum stays out of build scripts.
- 2026-11-04 · The table at run time (`file::parse`) leaks its strings to give the same `&'static` types as the generated code, so one renderer and one set of types serve both; a file is meant to be read once.
- 2026-11-04 · The accessor-name check takes the app's method names from the app (`Codegen::methods`) and keeps the Rust keywords in the kit; the refusal text stays Encore's ("taken by a Config method or a Rust keyword").
- 2026-11-04 · Encore's `Config` wraps the kit `Store` (`saved()`, then its one-time migration, then `apply()`), keeping its public API and `defs` field.
- 2026-11-04 · Encore-only save behaviour goes through `SettingsHost` hooks (`kept`, `unrevealed`, `before_save` returning `_warnings`, `after_save`, `log`, `owner`, `dump`); `before_save` runs before the activity-log line, as Encore's signup-mode check did.
- 2026-11-04 · `Store::load` creates the `settings` table if it is missing (for apps without migrations); Encore uses `Store::new` and its own reload, so it runs no new statement.
- 2026-11-04 · The Test button answers `{ok, message}` as Encore does, not `{ok, detail}` as the contract said; diagnostics.md and openapi.yaml are corrected.
- 2026-11-04 · A diagnostics check keeps its JSON object as the app built it, so Encore's numeric HTTP `status`, `body` and `ms` stay; a `status` that isn't ok/warn/fail counts as absent for the kit status.
- 2026-11-04 · Diagnostics groups all run at once (Encore ran only the HTTP checks together, then the folders and tools in turn); the answer and its order are the same.
- 2026-11-04 · On an app's own paths a notice is the app's object unchanged (no `id`/`severity`); only `/api/notices` adds them and gives non-admins `{ok}` alone.
- 2026-11-04 · Encore does not mount `/api/notices`; its storage notice has no kit timer, because Encore's worker already probes the download folders every minute.
- 2026-11-04 · App updaters take a full release only for tag `^v\d+\.\d+\.\d+$` (Android's rule; desktop accepted any 3-part semver), and use Android's newer-than rule on every platform.
- 2026-11-04 · The server-side release fetch and its sync_state cache (ETags, token, check_updates) stay in encore-system; the kit takes the parsing, channel, newer rule, shared answer and restart planning.
- 2026-11-04 · kit-server-changelog serves notes parsed by kit-rules `changelog` (the same `parse`/`unseen`/`Block`), so the server crate keeps no second copy of the parser.
- 2026-11-04 · Template: server/ and web/ are separate Cargo workspaces, as Encore's server/ and web-rs/, so the shared workflows take them as `rust-dirs: server`, `wasm-dirs: web`.
- 2026-11-04 · Template: the app reads `APP_PORT`, `APP_DATA_DIR`, `APP_STATIC_DIR` (Encore's `ENCORE_*` without the app name), so its Rust files carry no Liquid.
- 2026-11-04 · Template image: `gcr.io/distroless/cc-debian13:nonroot` (same glibc as the trixie builder); the health check is the binary's own `healthcheck` command, since distroless has no curl.
- 2026-11-04 · Template releases: the APK is built only on a manual run with "apps" ticked (it needs the app's signing secrets), as Encore's; the template has no desktop app (DESIGN.md §13 lists none), so kit-desktop is wired in when an app adds one.
- 2026-11-04 · Template CI: the kit's `template` job rewrites the generated app's `git = …Krifmaz/kit, tag = …` lines to path dependencies on the PR's own crates (a `[patch]` still needs the tag to exist).
- 2026-11-04 · Template sign-in is Encore's, cut down: owner at first start (`APP_ADMIN_USER`/`APP_ADMIN_PASSWORD`, else a printed password in `initial_admin_password.txt`), web session cookie `<app>_session`, `x-api-key` as the owner, phone app tokens (`Authorization: Bearer`, stored as SHA-256) and `/api/auth/prefs`; no sign-up, mail or two-factor, which an app adds when it needs them.
- 2026-11-04 · Template: the `X-Requested-With` value, the `x-<project>` mark on every server answer and the web app's event names use the project name (`kit-demo`), not the display name, because a header name may not hold spaces; the display name (`<meta name="application-name">`) is only in the words people read, so the template has its own small `watch_connection` instead of kit-leptos' one that builds both from one name.
- 2026-11-04 · Template server sets Encore's cache policy and security headers in one middleware: `no-store` for /api and index.html, `immutable` for trunk's hashed assets, `no-cache` for the rest.
- 2026-11-04 · Template notice: Encore's storage notice for the one folder the app writes to ("The data folder /data is read-only – check the disk (dmesg, fsck) or the mount"), at `/api/storage` and in `/api/notices`; Check again's words are Encore's downloads-folder sentences said of the data folder.
- 2026-11-04 · Template web: the brand shows the app's name without Encore's logo (the logo is Encore's own mark); the shell, sign-in card and bug report list keep Encore's markup and words.
- 2026-11-04 · Template web: copies of the kit's `design/out/tokens.css` and Encore's rules (`kit-leptos/demo/encore-app.css`) live in `web/static/css`, because a cargo-generate subfolder cannot reach the rest of the kit; the kit's CI fails when they differ.
- 2026-11-04 · Template: no Cargo.lock is shipped (it would name the kit tag's commit before it exists); the README says to run `cargo generate-lockfile` in server/ and web/ before the first push, since the shared CI builds with `--locked`.
- 2026-11-04 · `kit-android.yml` passes the run's `GITHUB_TOKEN` to Gradle so apps can read kit-compose from GitHub Packages without a secret of their own.

- 2026-11-04 · Template Android: the package is `dev.krifmaz.<crate name without underscores>` (`android_app`), since ktlint's package-name rule rejects underscores; sources live in `dev/krifmaz/{{android_app}}` because cargo-generate turns `/` inside a placeholder into `_`.
- 2026-11-04 · Template Android: Kotlin files are templated for their package line; the Gradle wrapper (`gradlew`, `gradlew.bat`, jar, Gradle 9.6.1) is shipped untemplated so a new app builds without a Gradle install (the shared workflow still uses the Gradle version the wrapper names).
- 2026-11-04 · Template Android: sign-in is Encore's phone sign-in (`POST /api/auth/login` with `app: {device_id, device_name}` → `{user, token}`, Bearer to the server's host only), with its authenticator-code step and words; a 401 later forgets the token and shows the sign-in again; `device_name` is Encore's `deviceName()`.
- 2026-11-04 · Template Android: sign-in errors show in full, selectable, with Copy, where Encore's sign-in shows plain red text, to follow the kit's copyable-errors rule.
- 2026-11-04 · Template Android: the first-start address rules and words are Encore's `EncoreApi.probe`; "an Encore server" becomes "a/an <App> server". Admin pages show unless `/api/auth/me` says the account isn't an admin; the server's 403 covers the rest.
- 2026-11-04 · Template Android: release signing, the debug `.debug` suffix, the manifest (update receiver, FileProvider, cleartext allowed) and the App crashes block are copied from Encore's app; no Baseline Profile is committed (the APK's comes from the libraries until the app generates its own on a device), and the benchmarks expect the app signed in once by hand.
- 2026-11-04 · Server crates take their routes as `XPaths` structs with neutral defaults (`router()` = `router_with(Default)`); bug reports' config reaches its handlers through an axum Extension.
- 2026-11-04 · Bug report status ids stay fixed; only their words are the app's. "Pick a kind" lists every configured kind, Crash log included.
- 2026-11-04 · `BugReportsHost::enrich` is dropped: an app adds its own fields in routes of its own.
- 2026-11-04 · SQL table names and pref keys of the server crates are kept as they are (already generic), so existing databases keep working.
- 2026-11-04 · kit-server-health's `web_build` takes the file prefix from the app and has no default (it is the app's file name).
- 2026-11-04 · kit-server-settings drops `listed_last`: it only kept one app's historical key order; keys are A to Z, and the file's order still sets pages, cards and fields.
- 2026-11-04 · Settings routes default to `/api/settings`, `/api/settings/schema`, `/api/settings/secret/{key}` (still admin, secret owner-only).
- 2026-11-04 · A settings card's `test` names a diagnostics check id; clients run it with `POST /api/diagnostics/<test>/test`.
- 2026-11-04 · `Codegen` keeps the optional typed accessors and the check against the accessor type's own method names; the refusal text says "a method of the settings type".
- 2026-11-04 · Diagnostics' unknown-test 404 says "Unknown check" (was "Unknown service"): the route names a check id now.
- 2026-11-04 · kit-server-notices replaces `router_at` (one notice at an app-named path) with the generic `GET /api/notices/{id}` and `POST /api/notices/{id}/check`, so a client banner that shows one notice needs no app route.
- 2026-11-04 · Update feed platforms are app-chosen string ids with `{version}` file name patterns, not a fixed enum, so an app can ship any set of builds.
- 2026-11-04 · Every platform's update version is read from the file name (was: APK from the file name, desktop from the tag); a release that did not rebuild a platform is then never offered for it.
- 2026-11-04 · `Feed::new` defaults to release prefix `v` and no hotfixes; an app opts into hotfixes with `.hotfix_prefix(...)`.
- 2026-11-04 · Template desktop: reqwest 0.12 with rustls on ring and webpki roots (not 0.13, whose default rustls uses aws-lc-rs and needs cmake/nasm on Windows), run on iced's tokio executor, so a request is a plain `async fn` in a `Task`.
- 2026-11-04 · Template desktop: the title and the release files' prefix come from a templated `desktop/app.json` read with `include_str!`, and the update feed from Cargo.toml's `repository` (`CARGO_PKG_REPOSITORY`), so the Rust files stay untemplated and need no build.rs.
- 2026-11-04 · Template desktop: what the app remembers (server, app token, install id, look, update switch) is one JSON file in the user's config folder, mode 0600 on Unix, rather than the system keychain, which would add a native dependency per system; `<PROJECT>_SERVER` overrides the address.
- 2026-11-04 · Template desktop: the release files are a Linux .tar.gz, a Windows .zip and a macOS .dmg (signed when the optional secrets exist); no AppImage or NSIS installer, so packaging needs no extra tooling on the runners. Install in the update notice downloads the file, checks it against SHA256SUMS and leaves it in Downloads with a Show toast, instead of replacing the running app.
- 2026-11-04 · Template desktop: the release workflow builds the desktop files only with "apps" ticked, like the APK (each release carries the previous files over), so a normal push to main does not spend Mac minutes.
- 2026-11-04 · Template desktop: the kit's `template` job also packages the Linux file (DESKTOP_PACKAGE=1) and runs `desktop/examples/walk.rs` against the generated server, so the desktop's client is proven against the real API, not only its pages headless.
- 2026-11-04 · Template desktop: the Look select offers kit-iced's `theme::THEMES` (the first, the default, is `theme::default_look()`; the others take their own accent); the logo is `desktop::LOGO`, kit-iced's neutral `Logo::KIT` until the app draws its own.
- 2026-11-04 · Scope change from the owner: the kit is a neutral base; nothing app-specific, no changes to other repos, the template's demo app is the only proof. Already-merged Encore PRs stay as they are (owner: "no need to revert").
- 2026-11-04 · Tokens: `encore` is the default theme and `:root`; every theme carries its own accent (encore/oled cream, dark violet, light charcoal); Encore-matching fixtures and Android overrides were removed; accents `logo` → `cream`, `encore` → `pastel`.
- 2026-11-04 · Shared workflows made neutral: kit-desktop calls the app's own `package` bash command with `$V`, `$RELEASE`, `$FEATURES`, `$ARGS`, `$OUT` (no fixed script path or `--stamp`/`--universal` flags); runner defaults are `ubuntu-latest`/`macos-latest`; NSIS is opt-in.
- 2026-11-04 · kit-release's `only: android` became `keep-previous: true` (any partial release keeps the previous release's other files, less `keep-drop`), so the input names no platform.
